API reference

The mini-lab API is compatible with OpenAI's Chat Completions API. Anything that speaks it (the official SDKs, curl, LangChain…) works by changing the base URL:

{{ base }}

{{ h2("quickstart", "Quickstart") }}

Create a key on the API keys page, export it, and send a message:

{{ code_block("doc-qs-curl", 'export MINILAB_API_KEY=sk-mini-... curl ' ~ base ~ '/chat/completions \\ -H "Authorization: Bearer $MINILAB_API_KEY" \\ -H "Content-Type: application/json" \\ -d \'{"model": "' ~ model_id ~ '", "messages": [{"role": "user", "content": "Tell me a story about a cat"}]}\'', lang="bash") }}

With the official Python SDK (pip install openai):

{{ code_block("doc-qs-py", 'import os from openai import OpenAI client = OpenAI(base_url="' ~ base ~ '", api_key=os.environ["MINILAB_API_KEY"]) response = client.chat.completions.create( model="' ~ model_id ~ '", messages=[{"role": "user", "content": "Tell me a story about a cat"}], ) print(response.choices[0].message.content) print(response.usage) # prompt_tokens, completion_tokens: what you are billed for', lang="python") }}

The models are tiny: they write short children's stories and do simple arithmetic (with a calculator). Don't expect more, that's the charm.

{{ h2("authentication", "Authentication") }}

Send your key as a bearer token: {{ c("Authorization: Bearer sk-mini-...") }}. Keys belong to a project inside an organization; every request is billed to that organization and logged with the key and project.

  • We store only a hash of each key, so a key is shown once, when you create it. Lost it? Revoke it and create a new one.
  • A revoked key is rejected immediately with {{ c("401 invalid_api_key") }}.
  • A key can have a spend limit: once reached, it gets {{ c("429 insufficient_quota") }} while other keys keep working.
  • Never put a key in client-side code: anyone who sees it can spend your credits.
{{ h2("chat-completions", "Chat completions") }}

{{ c("POST /v1/chat/completions") }} generates the next assistant message of a conversation.

ParameterTypeDescription
{{ name }}{{ type }}{{ desc }}

Parameters that would change the answer but aren't supported ({{ c("n > 1") }}, {{ c("logprobs") }}, JSON mode, penalties…) are rejected with a 400 rather than silently ignored. Unknown harmless fields such as {{ c("user") }} are ignored.

Response:

{{ code_block("doc-response", '{ "id": "chatcmpl-8f3a...", "object": "chat.completion", "created": 1790000000, "model": "' ~ model_id ~ '", "choices": [{ "index": 0, "message": {"role": "assistant", "content": "Once upon a time, there was a cat named Tom..."}, "finish_reason": "stop" }], "usage": {"prompt_tokens": 14, "completion_tokens": 58, "total_tokens": 72} }', lang="json") }}

{{ c("finish_reason") }} is {{ c("stop") }} (the model finished or hit a stop sequence), {{ c("length") }} (max tokens or context window reached) or {{ c("tool_calls") }}. The request id is also returned in the {{ c("x-request-id") }} header, and appears in your logs.

{{ h2("streaming", "Streaming") }}

With {{ c('"stream": true') }} the response is a {{ c("text/event-stream") }}: one {{ c("chat.completion.chunk") }} per {{ c("data:") }} line, as tokens are generated, then {{ c("data: [DONE]") }}.

{{ code_block("doc-stream", 'stream = client.chat.completions.create( model="' ~ model_id ~ '", messages=[{"role": "user", "content": "Tell me a story about a dog"}], stream=True, stream_options={"include_usage": True}, ) for chunk in stream: if chunk.choices and chunk.choices[0].delta.content: print(chunk.choices[0].delta.content, end="", flush=True) if chunk.usage: # last chunk, with include_usage print("\\n", chunk.usage)', lang="python") }}

If generation fails after the stream has started, a chunk with an {{ c("error") }} object is sent instead of more tokens (the SDKs raise it as an exception).

{{ h2("tool-calling", "Tool calling") }}

The models were trained to use one tool, a calculator, for arithmetic. Declare it in {{ c("tools") }}; when the model wants it, the response has {{ c("finish_reason: \"tool_calls\"") }} and {{ c("message.tool_calls") }}. Run the calculation yourself, append the result as a {{ c("tool") }} message, and call the API again for the final answer.

{{ code_block("doc-tools", 'tools = [{ "type": "function", "function": { "name": "calculator", "description": "Evaluate an arithmetic expression.", "parameters": {"type": "object", "properties": {"expression": {"type": "string"}}, "required": ["expression"]}, }, }] messages = [{"role": "user", "content": "What is 347 + 58?"}] response = client.chat.completions.create(model="' ~ model_id ~ '", messages=messages, tools=tools) message = response.choices[0].message if message.tool_calls: messages.append(message) for call in message.tool_calls: expression = json.loads(call.function.arguments)["expression"] # "347 + 58" result = my_safe_calculator(expression) # "405" (never eval() it!) messages.append({"role": "tool", "tool_call_id": call.id, "content": result}) response = client.chat.completions.create(model="' ~ model_id ~ '", messages=messages, tools=tools) print(response.choices[0].message.content) # "The answer is 405."', lang="python") }}

When streaming, tool calls arrive at the end, one chunk per call with its complete arguments. The playground and chat app run this loop for you on the server.

{{ h2("reasoning", "Scratchpad reasoning") }}

Some models think before answering. That scratchpad is returned separately from the answer, in the non-standard field {{ c("message.reasoning_content") }} ({{ c("delta.reasoning_content") }} when streaming), like other OpenAI-compatible servers do. It is billed as output tokens. The SDKs keep unknown fields, so {{ c("message.reasoning_content") }} works in Python.

{{ h2("rate-limits", "Rate limits") }}

Each key is limited in requests per minute (RPM) and tokens per minute (TPM). The defaults are {{ settings.default_rpm|num }} RPM and {{ settings.default_tpm|num }} TPM. The playground and chat app share one budget per organization.

Every response carries the current state in OpenAI's headers:

{{ code_block("doc-ratelimit", 'x-ratelimit-limit-requests: ' ~ settings.default_rpm ~ ' x-ratelimit-remaining-requests: ' ~ (settings.default_rpm - 1) ~ ' x-ratelimit-reset-requests: 1s x-ratelimit-limit-tokens: ' ~ settings.default_tpm ~ ' x-ratelimit-remaining-tokens: ' ~ (settings.default_tpm - 256) ~ ' x-ratelimit-reset-tokens: 384ms', lang="headers") }}

Over the limit you get {{ c("429 rate_limit_exceeded") }}. The SDKs retry these automatically with backoff.

{{ h2("pricing", "Pricing and billing") }}

Credits are prepaid. A request costs its prompt tokens times the model's input price plus its completion tokens times the output price (prices are per million tokens). It is deducted from your organization's balance as soon as it completes. When the balance reaches zero, requests get {{ c("429 insufficient_quota") }} until you add credits.
